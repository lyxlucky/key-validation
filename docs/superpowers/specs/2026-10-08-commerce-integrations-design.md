## 共同约束

复用运营规格中的权限、应用范围、后台事件/投递设施。订单、客户、卡密、渠道数据均由服务端隔离，不能仅靠隐藏按钮。金额使用整数分与 CNY；金额仅作人工结算记录。历史价格和授权条件在订单创建时保存快照。

本规格中的Admin管理能力按后续[标准RBAC规格](2026-10-09-administration-usability-design.md)使用`platform.manage`校验；有效业务权限为角色权限并集，应用与渠道范围独立。平台能力本身不隐含业务读取或Webhook管理权限。公开额度整数上限为9,007,199,254,740,991，单价分上限为90,071,992,547,409，保证最多100份的订单总价可被前端精确表示。

## F16 客户与订单

客户保存名称（必填，1–120）、可选邮箱/电话（最多254/40）、备注（500）、所属应用及可选渠道。一个客户只属于一个应用/渠道，避免跨范围推断。默认保留，不自动删除；管理员可停用与匿名化：清除姓名/联系方式/备注，撤销自助访问，保留不可反推身份的订单和审计关系。

订单类型 issue/renewal，状态 pending/fulfilled/cancelled。保存客户、应用、卡种、数量1–100、单价分、期限/设备/并发/功能快照、请求ID、创建/履约人和时间。renewal 数量为1，须指定该客户拥有的正式授权，时长遵守现有整数小时续期规则；冻结不允许续期。

管理员或具 `orders.manage` 的操作员创建和人工确认履约。履约在一个事务中锁定应用、渠道额度、订单和相关授权；issue 生成唯一批次及卡密关联，renewal 延长一次；重复请求/竞争不重复发卡、续期或扣额度。取消只允许 pending。

普通发卡仍只存摘要。订单交付密钥是明确的新交付通道：使用 Data Protection 加密保存，仅该客户的有效自助会话与有权操作员通过专用交付接口读取，默认30天后删除密文；普通列表、事件、日志、审计不返回明文。订单详情显示过期交付状态，不能恢复已清除明文。人工确认响应丢失后可查询原订单和交付，避免重复履约。

提供客户/订单分页、应用/渠道/状态/客户筛选、关联授权与履约历史。客户页面能追踪续期与换绑申请。

## F17 渠道

单级渠道，无分佣和资金支付。Admin 建渠道，绑定一个非 Admin 管理账号，指定应用集合、剩余发卡额度（非负整数）、卡种售价（整数分）。管理员调整额度须原因并留下不可变账本；每张正式发卡消耗1，续期订单消耗1；履约失败整体回滚。并发请求不透支，取消未履约订单不扣额度。

渠道账号只看自己的客户、订单、批次和授权，且与账号应用范围取交集。卡种可读，不能修改平台配置、给自己充值或变更售价。渠道发卡必须经订单履约入口，不能通过旧批量发卡绕过额度。渠道停用后新业务拒绝，既有客户授权保留原有效性。Admin 可汇总或按渠道筛选。

## F19 客户自助

由有权管理客户的人员生成256位随机访问码，一次展示，数据库只存摘要。通过商家已核实的交付渠道提供给客户；不以可猜客户编号或卡密提示作为凭据。访问码可轮换，轮换/停用/匿名化立即撤销旧会话。

`POST /api/portal/sessions` 以访问码换取8小时随机 Bearer 会话，摘要存储、限流，前端仅保存在当前浏览器会话。退出撤销，过期必须重新登录。门户使用独立路由与请求认证，不复用管理员 Cookie/缓存。

登录后查看自己的订单、交付、授权期限/状态/功能、设备；提交续期申请或指定自身绑定的换绑申请。续期申请由后台人工确认后建立/履约 renewal 订单，页面明确显示“待商家处理”。换绑申请 pending/approved/rejected，审批需要理由；批准遵守 F04 次数与冷却，原子释放设备、撤销会话并完成申请。重复审批不重复占用次数。客户不能修改额度、计划、价格或其他客户关系。

## F20 开放 API 与 Webhook

Admin 创建应用级随机 API 凭证，可绑定渠道，权限为明确的 `licenses.read`、`customers.manage`、`orders.manage` 子集。仅创建/轮换返回秘密，存摘要；凭证停用/轮换即时使旧值无效。每凭证60次/分钟并受全局限流，多实例共享网关规则记入部署说明。

`/api/v1` 供外部系统查询范围内授权、管理范围内客户和创建/履约/查询订单；所有 ID 与 body.applicationId 必须落在凭证应用/渠道范围，越权404。请求 ID 是必填的幂等键，内容变化返回409。没有账号管理、备份或提升权限入口。

应用级 Webhook 复用运营签名和重试机制，事件包括 order.fulfilled、license.renewed、binding.released、risk.detected、license.expiring。事件最少包含事件 ID、类型、时间、应用与资源引用；不含卡密、访问码或个人联系方式。订阅支持停用、秘密轮换、投递记录、人工重试。停用停止新投递，历史记录保留；不保证顺序，接收方按事件 ID 幂等。

## 验收

HTTP/真实数据库覆盖客户范围和匿名化、订单快照、并发履约只发一次/扣一次、失败整体回滚、续期及冻结边界、交付限期和授权、渠道不能越权或绕过额度、门户跨客户/撤销/申请审批、API凭证范围/轮换/幂等/限流、Webhook签名及无秘密泄露。浏览器完成客户建档→订单→人工履约→门户查看→换绑申请/审批，以及渠道配置和凭证管理。支付功能不计为完成。
