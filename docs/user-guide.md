## 1. 开始前：入口、术语和界面

### 1.1 准备好访问资料

本说明以系统已部署并正常运行为前提。开始操作前，向系统负责人领取后台地址、本人账号和初始密码；使用软件时，还需要软件程序、应用标识及完整卡密。

| 入口 | 用途 | 本工作区的本机示例 |
| --- | --- | --- |
| 管理后台 | 管理应用、卡密、客户、订单等 | `http://127.0.0.1:5173` |
| 客户自助 | 客户查订单、领取交付、申请售后 | `http://127.0.0.1:5173/portal` |
| API 地址 | 填在 Windows 测试台中，连接授权服务 | `http://127.0.0.1:5080` |

**`127.0.0.1` 表示正在操作的这台电脑。** 在其他电脑使用时，请使用系统负责人提供的正式网址和 API 地址。桌面程序连接远程服务需要 HTTPS；本机测试才使用上述 HTTP 地址。

系统没有通用的默认管理员账号或默认密码。后台使用“用户名＋密码”登录，客户自助使用商家提供的“客户访问码”登录。

### 1.2 先认识这几个名称

| 名称 | 可以这样理解 |
| --- | --- |
| 应用 | 一款被授权的软件，例如“培训演示软件” |
| 应用标识 | 软件连接服务时使用的代号，例如 `training-demo`；与应用名称不同 |
| 卡种 | 一套授权规则，例如 30 天、1 台设备、允许导出的“月卡” |
| 卡密 | 交给使用者激活软件的完整字符串 |
| 卡密标识／卡密提示 | 列表中用于识别卡密的脱敏内容，不能用来激活 |
| 卡密 ID／授权 ID | 系统内部定位一份授权的编号；离线签发中的“授权 ID”对应卡密详情中的“卡密 ID” |
| 批次 | 一次生成的一组卡密，方便追踪和统一处理 |
| 设备标识 | 客户端识别当前电脑的原始标识；与后台生成的“绑定 ID”不同 |
| 设备绑定 | 某张卡密已经占用的设备名额 |
| 会话／心跳 | 软件激活后的使用连接，以及定期向服务器确认授权的过程 |
| 订单履约 | 商家核对订单后，实际执行发卡或续期 |
| 客户访问码 | 客户进入自助服务的凭据，不能代替卡密激活软件 |

### 1.3 登录和使用界面

1. 用浏览器打开管理后台，输入“用户名”和“密码”，点击“登录”。
2. 若出现双重验证，输入认证器当前验证码，或切换到“恢复码”，点击“验证并登录”。
3. 若进入“账号安全”并提示“请先修改初始密码”，先完成修改，再进入业务页面。
4. 点击左侧菜单分组展开页面，其他分组会自动收起。侧边栏收起时，点击顶部“展开侧边栏”；窄屏下点击“打开导航”。
5. 点击列表右侧“详情”，通常会打开右侧详情面板；窄屏部分操作收在“操作”菜单内。
6. 工作结束后，点击右上角“退出登录”。

顶部工作区标签可在多个页面之间切换，保留当前筛选、分页、表单和滚动位置。**保留表单不代表已经保存**；离开前应点击对应保存按钮。关闭标签、刷新整个网页或退出登录可能丢失未提交内容。

| 菜单分组 | 常用页面 |
| --- | --- |
| 概览 | 查看授权总量、已激活卡密、有效授权和在线会话 |
| 授权管理 | 应用管理、卡密管理、批次管理、到期提醒、客户端版本、离线授权 |
| 客户与渠道 | 客户管理、订单管理、客户申请、渠道管理 |
| 运营与集成 | 运营统计、异常检测、通知中心、开放集成 |
| 系统管理 | 运维中心、操作日志、登录日志、账号管理、角色管理、账号安全 |

菜单和按钮随账号权限变化。找不到页面、只能查看不能修改，或看不到某个应用时，请让管理员检查“账号角色”“数据范围”和渠道归属。管理员、操作员、只读是内置角色名称，实际能操作什么以当前分配的权限为准。

## 2. 第一次使用：从创建应用到激活卡密

本章使用独立的培训应用和 1 张测试卡演示。创建应用与卡种需要平台管理权限；直接生成卡密需要发卡权限，渠道账号通过订单发卡。

操作顺序：**创建应用 → 创建卡种 → 生成并保存卡密 → 客户端激活 → 后台核对设备。**

### 2.1 创建应用

1. 打开“授权管理 → 应用管理”，点击“创建应用”。
2. 填写应用名称，然后点击“创建”。应用标识已自动生成，无需手工填写；有固定接入要求时也可自定义。

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 应用名称 | 培训演示软件 | 供后台人员识别 |
| 应用标识 | 自动生成，也可自定义为 `training-demo` | 使用 3–64 位字母、数字、短横线或下划线；创建后不可修改 |

创建成功后会打开应用设置，继续引用卡种。应用列表与设置页都支持一键复制应用标识；客户端使用实际创建的标识。列表可按名称或标识搜索所有页的应用。自定义标识若已存在，请修改后重试。

应用已经存在时，直接使用负责人指定的应用。

### 2.2 创建卡种

1. 打开“授权管理 → 卡种管理”。
2. 点击“创建卡种”，按下面示例填写。
3. 在“授权功能”中输入 `export` 后按回车，使它成为一个功能项。
4. 点击“保存卡种”，确认卡种列表出现该记录，发行状态为“可发行”。
5. 回到“应用管理”，打开该应用的“应用设置”。在“引用卡种”选择刚创建的卡种并点击“引用卡种”。多个应用可引用同一份规则。

| 字段 | 培训示例 | 填写说明 |
| --- | --- | --- |
| 卡种名称 | 培训月卡 | 例如日卡、月卡、年卡 |
| 授权时长 | `1` | 配合时长单位填写；从首次激活开始计时 |
| 时长单位 | 月 | 支持分钟、小时、天、月、年；1 天 = 24 小时，1 月 = 30 天，1 年 = 365 天，最长 10 年 |
| 设备上限 | `1` | 最多同时保留多少台设备绑定，允许 1–100 |
| 在线会话上限 | `1` | 最多同时有多少个有效在线会话，允许 1–100 |
| 激活期限（天） | 留空 | 限制发卡后多久必须首次激活；留空不限制 |
| 授权功能 | `export` | Windows 测试台的 CSV 导出需要此功能 |

“设备上限”和“在线会话上限”是两个限制。例如设备上限为 2、在线上限为 1，可以绑定两台电脑，但不能同时在线使用。同一设备重新激活会替换该设备的旧会话。

功能标识由软件接入方约定，留空表示未授予细分功能。添加一个名称并不会自动让软件具备该功能。

**卡种的时长、设备上限、在线上限、激活期限和功能会在发卡时固定。** 修改卡种只影响之后直接生成的卡密；已保存订单按订单中的规则快照履约。既有卡密不会因为编辑卡种而自动升级。

### 2.3 生成并保存卡密

1. 打开“授权管理 → 卡密管理”，点击“生成卡密”。
2. “所属应用”可按应用名称或标识搜索，选择刚创建的应用；“卡种”也可搜索，选择“培训月卡”。
3. 将“生成数量”改为 `1`，在“批次备注”填写“新人培训”。每次可直接生成 1–1000 张。
4. 点击“确认生成”。
5. 弹窗会直接切换到“卡密已生成”结果。点击“下载 CSV”，并确认文件已保存；也可“复制全部”后粘贴保存，或使用单张卡密旁的复制按钮。
6. 保存后再点击“已保存，关闭”。

**此入口生成的完整卡密只在本次结果中提供。** 关闭结果窗口、刷新网页后，不能从卡密列表或批次详情再次取回明文。请将 CSV 保存在受控位置，不要放入公开群聊或共享文档。

如果生成时断网并出现“存在待确认的发卡请求”，请保留当前页面，按[发卡结果不确定的处理方法](#issuance-recovery)操作。

直接生成的卡密不会自动归入某个客户。需要客户在自助服务中查看和领取时，请在应用、卡种准备好后，使用[客户建档和订单发卡流程](#customers-orders)。

### 2.4 用 Windows 测试台激活

本项目提供的“Windows 授权测试台”用于演示授权操作。实际交付软件的界面可能不同，请按交付软件的激活界面填写。

1. 打开交付目录中的 `KeyValidation.Desktop.exe`。本工作区当前版本位于 `samples/KeyValidation.Desktop/artifacts/win-x64-r3/`。
2. 程序需要 Windows x64 和 .NET 10 Windows Desktop Runtime；运行时保留同目录的 DLL 和配置文件。
3. 将“授权模式”选择为“在线授权”，填写下表。
4. 保持“自动心跳”开启，点击“卡密激活”。

| 字段 | 培训示例／操作 |
| --- | --- |
| API 地址 | 在本工作区电脑上填 `http://127.0.0.1:5080`；远程使用负责人提供的 API 地址 |
| 应用标识 | `training-demo`，或第 2.1 节实际创建的标识 |
| 客户端版本（可留空） | 培训填 `2.1.0`；正式使用填写真实的软件版本，开启强制版本限制时不能留空 |
| 设备标识（默认遮蔽） | 第一次操作保留程序自动生成的值 |
| 设备名称 | 培训电脑 |
| 卡密 | 粘贴第 2.3 节保存的完整卡密 |

API 地址填写服务根地址，不要在末尾追加 `/api`、管理页面路径或查询参数。

成功后，状态显示“在线有效”，可查看授权期限、功能和租约倒计时。点击“执行基础操作”应得到演示结果 `42`；点击“导出演示 CSV”，选择保存位置后应生成 CSV 文件。

默认约每 5 秒心跳一次，当前租约最多约 180 秒。网络中断或关闭自动心跳不会延长租约；租约到期后受保护操作停止。单次会话最多 8 小时，届时需要重新激活，卡密本身的有效期不会因此增加。

### 2.5 回到后台核对

1. 打开“卡密管理”，选择培训应用，点击这张卡的“详情”。
2. 核对状态为“有效”，已经记录“激活时间”和“到期时间”。
3. 在“设备绑定”找到“培训电脑”，确认已绑定数量、最近心跳及会话状态。

至此完成了从配置到使用的一轮操作。程序不会自动保存卡密和会话令牌，下次需要时从自己保存的交付文件中取用卡密。

### 2.6 Windows 测试台常用按钮

| 按钮／开关 | 什么时候使用 | 操作结果 |
| --- | --- | --- |
| 载入测试配置 | 负责人已经提供测试配置 JSON 文件 | 选择文件后填入配置，仍需手动点击激活、领取试用或验证离线授权 |
| 显示敏感输入 | 需要核对卡密或设备标识 | 临时显示被遮蔽的输入，核对后可关闭 |
| 立即心跳 | 核实当前在线授权，或验证后台管控效果 | 立即向服务端请求确认，查看最新状态和提示 |
| 自动心跳 | 正常在线使用时 | 保持开启；关闭后当前租约仍继续倒计时 |
| 退出会话 | 结束当前在线使用 | 结束本地权限，服务端确认后显示退出成功；保留设备绑定 |
| 释放当前设备 | 准备更换电脑 | 按换绑规则请求解绑当前设备；先确认成功，再在新电脑激活 |
| 清除本地授权 | 结束本地状态或重新填写配置 | 清除本地权限并取消旧请求，不能据此认定服务端已退出 |

授权期间部分配置会锁定。需要修改时，先“退出会话”；只需结束本地状态时可“清除本地授权”。诊断和使用帮助位于“诊断与帮助”标签页。

## 3. 日常卡密管理与售后

### 3.1 找到需要处理的卡密

打开“授权管理 → 卡密管理”，根据手头信息选择一种查找方式。

| 手头的信息 | 操作方法 |
| --- | --- |
| 完整卡密 | 在“完整卡密查找”输入，点击“查找” |
| 应用、卡密状态 | 使用页面上方的应用和状态下拉框 |
| 批次 ID、备注、标签 | 填写对应条件，点击“筛选”；标签精确匹配单个标签 |
| 发行、激活、到期日期 | 打开“高级筛选”，填写日期后点击“筛选” |
| 原始设备标识 | 先选择应用，再在“高级筛选”填写“设备标识（精确匹配）”，点击“筛选” |

多个条件同时满足才会列出记录。按设备查找包含当前和历史绑定；日期筛选包含结束日，使用当前电脑时区。找不到时先点击“重置”，再逐个增加条件。

### 3.2 看懂卡密状态

| 状态 | 含义 | 常见处理 |
| --- | --- | --- |
| 未激活 | 尚未首次激活，使用时长尚未开始 | 将完整卡密交给使用者，在最晚激活时间前激活 |
| 有效 | 已激活且未到期 | 正常使用，必要时续期或处理设备 |
| 已过期 | 已达到授权到期时间 | 按客户需求办理续期 |
| 已禁用 | 人工停止使用 | 核实原因后恢复；还要检查应用状态和有效期 |
| 已冻结 | 暂停授权使用和剩余时间计时 | 核实后解冻，再让客户端重新激活 |
| 激活超期 | 在规定期限内没有首次激活 | 联系有权限的人员重新发行；增加授权时长不会重设激活期限 |

应用本身被禁用时，即使卡密看起来仍在有效期内，也不能正常激活或心跳。冻结与禁用可以同时存在，请同时检查详情中的提示。

### 3.3 办理续期

平台直营卡密可以在详情中直接续期；渠道卡密需要通过“订单管理”创建并履约续期订单。

1. 在“卡密管理”找到卡密，点击“详情 → 续期卡密”。
2. 填写“延长时长（小时）”，例如续 30 天填 `720`。
3. 填写“操作原因”，例如“客户续费 30 天”，点击“确认执行”。
4. 查看“操作结果”，确认成功，并核对新的授权时长或到期时间。

| 续期前状态 | 如何计算 |
| --- | --- |
| 未激活 | 增加首次激活后可使用的时长，不开始计时 |
| 已激活、未过期 | 从原到期时间继续增加 |
| 已过期 | 从服务端当前时间开始增加 |
| 已冻结 | 不能续期，先解冻 |
| 已禁用 | 续期不会自动恢复，需要另行判断是否恢复 |

每次延长 1–87600 个整数小时，续期后仍受系统十年上限约束。设备绑定保持不变；已经失效或撤销的会话不会恢复，客户端需要重新激活。

### 3.4 选择正确的管控操作

| 你想达到的效果 | 入口与按钮 | 对授权的影响 |
| --- | --- | --- |
| 停止使用某张卡 | 卡密详情 →“禁用卡密”→“确认禁用” | 撤销现有会话，拒绝激活和心跳；禁用本身不暂停计时 |
| 允许被禁用的卡继续使用 | 卡密详情 →“恢复卡密”→“确认恢复” | 不延长到期时间，不恢复旧会话；仍需满足其他授权条件 |
| 暂停使用并保留剩余时长 | 卡密详情 →“冻结与解冻”→“冻结授权” | 填写“操作原因”并“确认冻结”；撤销会话并暂停计时，仅有效状态可发起冻结 |
| 恢复冻结时剩余时长 | 同一区域 →“解冻授权” | 填写原因并“确认解冻”；从解冻时刻恢复剩余时间，不会解除另行设置的禁用 |
| 仅结束某次软件连接 | 卡密详情 → 设备绑定 → 设备会话 →“撤销” | 保留设备名额和卡密有效期，客户端可以按规则重新激活 |
| 给新电脑腾出设备名额 | 卡密详情 → 对应设备 →“解绑设备” | 释放该设备名额并撤销其会话；有效期不变，受换绑规则限制 |

后台管控在服务端生效后，在线客户端会在后续请求中收到拒绝；没有联网成功的客户端最多继续使用上一份有效租约。对离线许可证的影响见第 8.3 节。

### 3.5 为客户换电脑

1. 找到卡密详情，在“设备绑定”核对旧电脑的名称、绑定时间和绑定 ID。
2. 查看下方“设备换绑”的剩余次数、冷却时间和“下次允许时间”。
3. 在旧电脑对应的设备卡片上点击“解绑设备”，核对后点击“确认解绑”。
4. 确认旧设备显示“已解绑”，已绑定数量减少。
5. 让客户在新电脑上使用原完整卡密重新激活，再确认新设备出现。

成功释放一条设备绑定计为一次换绑。当前新发卡默认采用滚动 30 天内最多 3 次、冷却 24 小时的限制；历史卡或调整过的卡以详情为准。后台解绑、客户端释放和审批换绑申请都受规则约束。

需要调整时，点击“设置换绑规则”，填写次数、滚动窗口、冷却时间及“调整原因”，点击“保存规则”。确需售后重置时，点击“重置次数与冷却”，填写原因并保存；重置保留历史，也不会自动解绑任何设备。重置完成后仍需执行对应的解绑操作。

### 3.6 编辑备注、标签和批量处理

单张卡：在详情点击“编辑备注标签”，填写备注、标签和操作原因，点击“确认执行”。标签输入后按回车，每张卡最多 10 个标签，每个不超过 32 字。

批量操作：

1. 先筛选出需要处理的记录，再勾选当前页的卡密。
2. 点击“批量续期”“批量编辑备注标签”“批量禁用”或“批量恢复”。
3. 核对弹窗中的操作和张数，填写参数及“操作原因”，点击“确认执行”。
4. 查看结果中的成功、失败数量和每张卡的说明，单独处理失败项。

选择只针对当前页，翻页或改变查询条件后需重新勾选。**批量编辑备注和标签会整体替换，留空表示清空**，不会在每张卡原有内容后追加。

若断网后出现“有一项卡密操作待确认”，点击“处理待确认操作”，先“检查操作结果”，必要时“使用原请求重试”。结果未确认前保留当前页面和请求信息，避免重新发起另一轮续期。

### 3.7 批次管理和到期提醒

**按批次处理：** 打开“授权管理 → 批次管理”，按应用、卡种、签发人 ID 或批次备注筛选。点击“详情”核对数量和签发信息，点击“查看卡密”查看这一批卡。需要全部停用时点击“禁用批次”，核对批次和总张数后再确认。批次“已激活”和“已禁用”数量可能重叠，不能简单相加。

**跟进到期：** 打开“授权管理 → 到期提醒”，选择“3 天内”“7 天内”或“30 天内”，再按应用、渠道筛选。列表按到期时间由近到远排列，点击“详情”办理后续处理。窗口从服务端当前时间开始，按每天 24 小时计算；尚未激活、已禁用或所属应用被禁用的卡不在该提醒范围内。

<a id="issuance-recovery"></a>

### 3.8 发卡结果不确定或卡密文件遗失

**发卡请求中断：** 再打开“生成卡密”，在待确认提示中点击“检查已创建批次”。尚未找到时可“使用原请求重试”；若已找到批次但明文没有收到，只能在核实该批次未正常交付后点击“禁用原批次”，确认禁用，再生成新批次。记录原请求标识和批次 ID，方便追查。

**已经关闭结果窗口且 CSV 遗失：** 先找自己的下载目录、备份或已保存的交付记录。直接发卡的后台列表无法补回明文。确需补发时，先查清遗失的是哪些卡，按售后决定禁用原卡或原批次，再重新发行，避免误停用同批次中已经正常使用的客户。

订单交付的取回方式不同，见第 4.3 节。

### 3.9 管理员维护应用和卡种

**修改卡种：** 打开“授权管理 → 卡种管理”，点击对应卡种的“编辑”，修改参数后点击“保存卡种”。修改影响所有引用应用后续的新卡和新订单；已有卡密、已创建订单保留快照。关闭“允许继续发行”会全局停发。在“应用管理 → 应用设置”关闭某个卡种的“本应用发行”只暂停该应用，历史记录仍可查询。全局管理和引用维护要求平台管理权限、全部应用范围且无渠道限制。

**停用整个应用：** 在“应用管理”的应用行点击“禁用”，确认影响后点击“确认禁用”。该应用的卡密不能继续激活，现有会话会被撤销，影响范围是整个应用。恢复时在同一行点击“恢复 → 确认恢复”，再让客户端重新激活；旧会话不会恢复。

<a id="customers-orders"></a>

## 4. 客户建档、订单与申请审批

需要关联客户、保留销售记录或让客户自己领取卡密时，使用本章流程：**新建客户 → 新建订单 → 核对并履约 → 交付卡密 → 提供客户访问码。**

### 4.1 新建客户

1. 打开“客户与渠道 → 客户管理”，点击“新建客户”。
2. “客户应用”选择客户购买的软件，填写“客户名称”；邮箱、电话、备注按需填写。
3. 管理员可选择“所属渠道”，不选择表示平台直营。渠道人员创建的客户受自己的渠道范围限制。
4. 点击“保存客户”，确认列表出现客户档案。

客户所属应用和渠道在建档后保持固定。资料需要修正时，在列表点击“编辑”；点击“详情”可以查看关联授权，并通过“查看客户订单”或“查看续期与换绑申请”继续处理。

### 4.2 创建并履约发卡订单

1. 打开“客户与渠道 → 订单管理”，点击“新建订单”。
2. 选择“订单应用”“订单客户”，将“订单类型”设为“发卡”。
3. 选择“订单卡种”，填写“订单数量”和“单价（分）”。
4. 点击“保存订单”。此时状态为“待履约”，尚未实际发卡。
5. 打开该订单“详情”，核对客户、卡种、数量、金额、时长、设备上限和功能快照。
6. 确认可以交付后，点击“确认履约”，在确认窗口点击“完成履约”。
7. 确认订单变为“已履约”，再领取交付内容。

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 订单数量 | `1` | 发卡订单允许 1–100 份 |
| 单价（分） | `9900` | 表示人民币 99.00 元；渠道客户使用管理员配置的渠道售价 |
| 卡种 | 培训月卡 | 订单保存授权规则快照，之后修改卡种不会自动改动此订单 |

当前订单采用人工履约，金额用于人工结算记录，系统未提供在线支付流程。实际收款和交付条件由商家核实。

填写错误且尚未履约时，在详情点击“取消订单”，确认取消后重新创建。已履约订单不能取消；需要处理已交付授权时，按售后规则操作关联卡密。

若保存订单时结果不确定，使用提示中的“继续处理”或重新打开“新建订单”，点击“查询并重试原订单”。若履约时连接中断，先“刷新详情”核对状态；仍需重试时继续操作原订单，不要重新建一笔相同订单。

### 4.3 保存并交付卡密

1. 在已履约的发卡订单详情点击“查看交付”。
2. 在“订单交付”窗口点击“下载卡密”保存文本文件，或“复制全部”。
3. 将卡密、对应软件、应用标识及需要的连接信息交给已核实的客户。
4. 告知客户如何激活，以及设备数量和有效期限制。

订单交付内容会保留到页面显示的截止时间，默认保留 30 天。**在保留期内关闭交付窗口后，可以再次领取；到期或清除后无法恢复明文。** 订单历史和授权关系仍然保留。

因此，“生成卡密”的一次性结果窗口与“订单交付”的保留期不能混用理解。两种方式都应及时保存交付文件。

### 4.4 给客户开通自助入口

1. 在“客户管理”找到客户，点击“访问码”。
2. 核对客户名称，点击“生成新访问码”。
3. 在“保存客户访问码”窗口点击“复制”，保存后再关闭。
4. 将**客户自助网址、客户访问码**和第 5 章操作步骤交给客户。

访问码仅在生成后显示一次。再次生成会立即使旧访问码和原自助登录失效，届时需要把新码交给客户。

### 4.5 通过订单续期

1. 在“订单管理 → 新建订单”选择应用和客户。
2. 将“订单类型”改为“续期”，选择“订单卡种”。
3. 在“续期授权”选择该客户需要延长的正式授权，填写“续期时长（小时）”及金额。
4. 续期订单数量固定为 `1`。保存后打开详情，核对授权对象、时长和金额。
5. 点击“确认履约 → 完成履约”，确认订单状态和授权的新到期时间。

渠道卡密使用此流程办理续期，履约会消耗 1 个渠道额度。冻结的授权应先处理解冻，续期不会自动解除禁用。

### 4.6 审批客户提交的申请

1. 打开“客户与渠道 → 客户申请”，将“处理状态”筛选为“待商家处理”。
2. 点击申请右侧“审批”，核对客户、申请类型、原因和对应授权。
3. 在“审批结果”选择“批准申请”或“拒绝申请”，填写“审批原因”。
4. 批准续期时，还需选择“续期卡种”、填写时长和单价。
5. 点击“保存审批”，在列表或“查看结果”中核对处理结果。

**批准续期会立即创建并履约续期订单。** 渠道申请使用渠道售价，并扣除 1 个额度。批准换绑会按现有换绑规则释放申请指定的旧设备，结束其会话；不会自动把新电脑绑定进去，客户仍需在新电脑激活。

只提交申请不会改变授权。审批失败时先查看提示，处理额度、冻结、冷却或次数限制后再核对原申请。

### 4.7 停用和匿名化客户

| 操作 | 影响 |
| --- | --- |
| 停用 | 停止该客户的新业务并撤销自助会话，已有授权仍按原规则保留 |
| 恢复 | 恢复新业务使用，旧自助会话不会恢复 |
| 匿名化 | 清除姓名、联系方式和备注，撤销自助访问；订单、授权关系保留，清除的个人资料无法恢复 |

需要停止客户的软件使用时，还应检查对应卡密并执行禁用等操作。匿名化适用于明确的数据清理需求，不作为一般售后停用步骤。

<a id="customer-portal"></a>

## 5. 客户自助服务操作

本章可以单独提供给客户。商家需要提前提供自助网址和客户访问码。

### 5.1 进入自助服务

1. 用浏览器打开商家提供的客户自助网址，通常为管理站点网址后加 `/portal`。
2. 在“客户访问码”输入商家提供的访问码，点击“进入自助服务”。
3. 登录后可以切换“我的订单”“我的授权”“我的申请”。

访问码不同于软件卡密。访问码遗失、被商家重新生成或客户被停用时，请联系商家处理。页面底部显示本次登录有效期，过期后需要重新登录。

### 5.2 领取订单中的卡密

1. 打开“我的订单”，找到对应订单，点击“详情”。
2. 若显示“待履约”，等待商家确认交付；可以点击“刷新订单”查看最新状态。
3. 已履约且仍在交付保留期内时，点击“领取交付”。
4. 在交付窗口点击“下载卡密”或“复制全部”，自行保存后再关闭。
5. 打开购买的软件，将完整卡密填入软件激活界面。

若显示交付内容已不可取回，请先检查已下载文件，再联系商家。列表里的授权标识不能代替完整卡密。

### 5.3 查看授权和申请续期

1. 打开“我的授权”，查看卡密状态和到期时间。
2. 点击“详情”，核对需要续期的授权，点击“申请续期”。
3. 在“申请原因”写清需求，例如“希望续期 30 天”，点击“提交申请”。
4. 打开“我的申请”，点击“刷新进度”，查看商家的处理结果和回复。

商家批准后才会实际续期，提交申请本身不会延长时间。试用或冻结状态可能无法申请续期，请联系商家。

### 5.4 更换电脑时申请换绑

1. 打开“我的授权 → 详情”，在“我的设备”中找到需要释放的旧电脑。
2. 点击该设备旁的“申请换绑”，填写原因后“提交申请”。
3. 在“我的申请”查看审批进度。
4. 商家批准、旧设备解绑后，在新电脑使用原卡密重新激活。

换绑受次数和冷却时间限制。批准后旧电脑的当前会话结束，授权到期时间保持不变。使用完客户自助后，点击右上角“退出自助服务”。

## 6. 渠道开通与管理

本章由有平台管理权限的管理员操作。渠道人员使用分配给自己的后台账号管理客户和订单。

### 6.1 开通一个渠道

1. 在“系统管理 → 账号管理”准备一个已启用的非管理员账号，分配其工作所需的角色和应用范围。该账号不能拥有平台管理权限。
2. 打开“客户与渠道 → 渠道管理”，点击“新建渠道”。
3. 填写“渠道名称”，选择“渠道账号”和“授权应用”，填写“初始额度”。
4. 点击“保存渠道”，确认渠道为“已启用”。一个后台账号不能同时关联其他渠道。
5. 点击渠道“详情 → 设置售价”，先选择“定价应用”，再选择“定价卡种”，填写“售价（分）”，点击“保存售价”。同一卡种在不同应用下可以分别设置售价；可提前为暂停发行的引用定价。
6. 让渠道人员重新登录，按客户建档、订单发卡流程操作。

渠道范围和账号应用范围会同时生效。即使渠道勾选了某应用，如果账号的数据范围不包含该应用，仍然无法访问。创建渠道不会自动补齐账号的业务权限。

### 6.2 调整额度与查看账本

1. 在“渠道管理”打开渠道“详情”，核对当前剩余额度。
2. 点击“调整额度”，在“调整数量”输入正数增加、负数扣减。
3. 填写“调整原因”，点击“确认调整”。调整量不能为 0，扣减后余额不能低于 0。
4. 查看更新后的余额和额度账本，核对变动数量、原因和时间。

每张正式发卡消耗 1 个额度，每笔续期订单消耗 1 个额度。额度在订单履约时扣除，取消待履约订单不会扣除额度。

结果不确定时，使用“继续确认”或“重试原调整”，保留原请求，不要再新建相同的额度调整。

### 6.3 改价与停用

修改售价仍在“详情 → 设置售价”完成，新的价格用于之后创建的渠道订单，已有订单保留原金额快照。

在渠道列表点击“停用”会停止该渠道的新业务，已有客户端授权继续按原规则验证。需要停止某张卡的使用时，另外处理对应卡密。恢复经营时点击“启用”，并检查账号、应用范围、售价和额度是否齐全。

<a id="accounts-security"></a>

## 7. 后台账号、角色与账号安全

### 7.1 创建后台账号

1. 管理员打开“系统管理 → 账号管理”，点击“创建账号”。
2. 填写“用户名”“初始密码”，选择 1–20 个“账号角色”。
3. 点击“创建账号”，在列表确认账号已启用。
4. 点击该账号“数据范围”，按职责保留“全部应用”，或关闭后选择“允许访问的应用”，点击“保存范围”。
5. 将后台网址、用户名和初始密码交给本人，首次登录按提示修改密码。

用户名使用字母、数字或 `- . _ @ +`。密码至少 12 位，包含大写字母、小写字母、数字和符号；保存后不会回显密码。

“全部应用”关闭且一个应用都不选时，该账号无法访问应用数据。渠道关联在“渠道管理”配置；“数据范围”用于设置账号本身允许的应用。

### 7.2 设置角色和处理账号问题

**创建角色：** 打开“角色管理 → 创建角色”，填写“角色名称”“角色说明”，勾选“操作权限”，点击“保存角色”。再回“账号管理 → 调整角色”把角色分配给人员，点击“保存修改”。

一个账号获得其所有角色权限的合并结果；数据范围仍单独限制能操作哪些应用和渠道。空角色不授予操作权限。内置管理员角色受保护；有成员的角色需要先调整成员，才能删除。

| 场景 | 操作 | 操作后的要求 |
| --- | --- | --- |
| 人员职责变化 | 账号管理 → 调整角色／数据范围 | 相关账号重新登录 |
| 忘记后台密码 | 账号管理 → 重置密码 → 输入新密码 → 保存修改 | 所有旧登录失效，将新密码交给本人按提示登录改密 |
| 停止账号使用 | 账号管理 → 停用账号 → 确认停用账号 | 不能继续登录，旧登录立即失效 |
| 恢复账号 | 账号管理 → 恢复账号 | 重新登录，原登录状态不恢复 |

角色权限被修改时，该角色的相关成员也需要重新登录。系统不允许停用自己或降低自己的权限，并要求至少保留一位启用的管理员。

### 7.3 自己修改密码

1. 打开“系统管理 → 账号安全”，点击“修改密码”。
2. 填写“当前密码”“新密码”“确认新密码”。新密码应满足复杂度要求，且不能与旧密码相同。
3. 点击“保存修改”，确认安全设置更新。

本人改密后，其他设备上的后台登录立即失效，本次登录保留。

### 7.4 开启双重验证和保存恢复码

1. 在“账号安全”点击“开启双重验证”，输入当前密码，点击“保存修改”。
2. 使用手机认证器扫描二维码，或手动录入页面密钥。
3. 输入认证器新生成的验证码，点击“确认开启”；设置窗口有效期为 5 分钟。
4. 在“保存恢复码”窗口保存全部恢复码，再点击“已安全保存，关闭”。

恢复码只在生成时显示，每个可替代认证器完成一次验证。二维码、密钥和恢复码应由账号本人保管。

需要更换恢复码时，点击“重新生成恢复码”，输入当前密码并保存。生成后全部旧恢复码立即失效。关闭双重验证同样只需确认当前密码。

双重验证在登录时完成一次，本次登录会话内的后续操作无需重复输入验证码。会话空闲 30 分钟或达到 8 小时上限后，需要重新登录并验证；密码重置、账号停用等也会结束失效的会话。刚用过的认证器验证码不能再次使用，请等待新码。

## 8. 试用、客户端版本与离线授权

### 8.1 开放试用和升级正式授权

1. 管理员打开“应用管理 → 应用设置”，找到“试用授权”区域，点击“配置试用”。
2. 开启“允许领取试用”，填写“试用时长（小时）”和“试用功能”，点击“保存试用规则”。
3. 在 Windows 测试台选择“在线授权”，填写正确的 API 地址、应用标识和版本，点击“领取试用”。
4. 查看授权状态和期限；需要升级时，在同一设备输入正式卡密，点击“卡密激活”。

每台设备在同一应用只能领取一次试用，重复领取不会增加时长；已使用正式授权的设备不能重新领取试用。修改试用规则只影响之后首次领取的设备，关闭领取不会提前终止已经发放的试用。

培训时使用专门的测试设备标识。正式使用应保持稳定的设备标识，便于识别设备、处理售后和执行试用规则。

### 8.2 设置客户端版本要求

1. 管理员打开“授权管理 → 客户端版本”，在“版本策略应用”选择应用。
2. 填写“最低支持版本”和“最新版本”，例如 `2.1.0`、`2.10.0`。
3. 按需要填写“更新地址”“安装包 SHA-256”和“发布说明”。更新地址使用 HTTPS。
4. 需要拒绝低版本时开启“强制最低版本”，点击“保存版本策略”。
5. 让测试人员用符合和不符合要求的版本分别验证激活、心跳结果。

版本必须是三段数字，每段 0–9999，不能有多余的前导零，例如 `2.01.0` 不符合要求。填写最低版本时还要填写最新版本，最新版本不能更低。

启用强制限制后，缺少版本或版本过低的客户端会在激活、心跳时被拒绝，已有在线会话也会受影响。发布前应确认可用的升级包和更新地址已经准备好。Windows 测试台的“检查公开版本”可查看版本信息，但不会激活软件，也不会自动下载或安装更新。

### 8.3 签发和使用离线许可证

适用于已接入离线验证的软件。开始前应满足：服务端离线签名配置已完成；正式卡密已经在线激活且仍有效；目标电脑已有有效设备绑定。

**后台签发：**

1. 在“卡密管理 → 详情”记录“卡密 ID”，以及目标设备的“绑定 ID”。
2. 从该设备的客户端取得激活时使用的原始“设备标识”。设备名称、绑定 ID 不能代替它。
3. 打开“授权管理 → 离线授权”，确认“签名配置”为“可签发”，点击“签发离线授权”。
4. 填写下表，核对后点击“确认签发”。
5. 在“保存离线许可证”窗口点击“下载保存”，保存 `.kglicense` 文件后再关闭。
6. 点击页面“导出验签公钥”，保存公钥 JSON，通过可信的软件交付渠道提供给客户端使用者。

| 字段 | 从哪里取得／如何填写 |
| --- | --- |
| 授权 ID | 卡密详情中的“卡密 ID” |
| 绑定 ID | 卡密详情中目标电脑的“绑定 ID” |
| 原始设备标识 | 目标电脑在线激活时提交的完整设备标识，必须一致 |
| 有效小时 | 1–168 个整数小时，签发窗口默认 24；实际期限不超过卡密当前到期时间 |

**Windows 测试台使用：**

1. 在目标电脑打开测试台，确认“应用标识”和“设备标识”与签发对象一致。
2. 将“授权模式”切换为“离线验证”。
3. 点击“选择离线许可证”，选中收到的 `.kglicense` 文件。
4. 点击“选择独立可信公钥”，选中商家通过可信渠道提供的公钥 JSON。
5. 点击“验证离线授权”，确认验证成功，再尝试“执行基础操作”或“导出演示 CSV”。导出仍需 `export` 功能。

离线模式不向服务器发请求。许可证丢失时不能从签发列表重新下载原文件，需要重新签发；同一绑定重新签发会替代旧签发记录。

**离线撤销有延迟。** 后台禁用、冻结、解绑或在“离线授权”列表点击“撤销”，已经离线的设备仍可能使用到旧许可证到期，最长延迟为剩余离线期限。重新签发也不能即时收回已经离线的旧文件。

如果页面显示“已关闭”“未配置完成”，交由系统运维人员配置后再签发。出现文件无效、错设备、到期或可信时间异常时，先核对文件和设备并联系支持人员，不要通过修改系统时间或删除可信时间记录处理。

## 9. 统计、通知、异常与日志

### 9.1 查看概览和运营统计

“概览”适合每天快速查看卡密总量、已激活卡密、有效授权、在线会话和最近发行记录。

需要按时间、应用或卡种分析时：

1. 打开“运营与集成 → 运营统计”。
2. 选择“统计应用”“统计卡种”及需要的渠道。
3. 填写“统计起始日（UTC）”“统计结束日（UTC）”，点击“查询区间”；一次最多查询 366 天，包含结束日。
4. 查看汇总卡片和“每日趋势”，在“应用与卡种”“每日明细”中查看数字；需要更新时点击“刷新统计”。

统计按 **UTC 自然日**计算，普通详情时间按当前电脑时区显示。北京时间比 UTC 快 8 小时，对比跨日数据时需考虑这一差异。

“首次激活”按授权去重；“在线授权”“在线会话”是当前状态，不是所选日期内的累计在线次数。“已到期”按当前到期时间计算，续期后数字可能变化。

### 9.2 查看与设置通知

**查看通知：** 打开“运营与集成 → 通知中心”，按应用筛选，按需开启“仅看未读”。看完一条后点击“标为已读”。这里显示发送给当前账号的站内通知。

**管理员设置：** 点击“通知设置”，选择“通知应用”，开启“启用通知”，选择“接收账号”“通知事件”和提前 3／7／30 天提醒的选项，点击“保存设置”。接收账号必须已启用且有权访问该应用。

到期提醒按授权当前的到期时间产生，续期后可产生新的提醒。需要推送给外部系统时，另行配置 Webhook。

### 9.3 复核异常

1. 打开“运营与集成 → 异常检测”，按“风险应用”和“复核状态”筛选。
2. 点击“复核”，阅读规则、统计窗口、证据摘要；需要时展开“检测证据”或点击“查看授权”。
3. 选择“确认异常”或“排除异常”，填写“复核原因”，点击“保存复核”。

管理员可通过“风险策略”选择应用，开启“记录异常”，设置激活次数、换绑次数及相应时间窗口，点击“保存策略”。“立即扫描”可触发一次检查。

复核只记录处理结论，不会自动禁用卡密。需要限制使用时，另到卡密详情执行操作。地区变化判断依赖可信地区来源，相关配置未完成时不能据此判断异常。

### 9.4 查操作记录和登录记录

| 需要查什么 | 入口 | 如何操作 |
| --- | --- | --- |
| 谁修改了卡密、应用、订单或账号 | 系统管理 → 操作日志 | 选择操作类型，输入操作人或对象 ID 搜索，选择日期范围，点击“查看详情” |
| 谁在什么时候登录、失败或退出 | 系统管理 → 登录日志 | 选择登录事件，搜索账号名称，选择日期范围，点击“查看详情” |

详情中核对操作者、对象、结果及可用的变更记录。旧记录缺少来源或字段信息时会显示“未记录”，不能把缺少记录直接理解为该操作从未发生。需要重新查找时点击“重置”。

## 10. 开放集成与运维

本章供负责系统接入、通知对接和运维的人员使用。普通发卡或客户激活完成前面流程即可。

### 10.1 创建商家服务端 API 凭证

1. 管理员打开“运营与集成 → 开放集成”，切换到“API 凭证”。
2. 点击“创建凭证”，填写“凭证名称”“凭证应用”，按需设置“限定渠道”。
3. 在“允许操作”中选择实际需要的“读取授权”“管理客户”“管理订单”，点击“保存凭证”。
4. 在“保存 API 凭证”窗口复制并保存凭证，交给负责配置商家服务端的人员。
5. 接入步骤查看同页“接入说明”。

凭证只在创建或轮换时显示。通过“编辑”可调整权限和“启用凭证”状态；点击“轮换凭证”并确认后，旧值立即失效，需要同步更新调用方。应用和渠道归属在创建后保持固定。

业务 API 凭证用于商家服务端调用，不应填入普通软件的卡密输入框。每个凭证每分钟最多 60 次请求，调用方遇到限流应按提示等待。

### 10.2 配置 Webhook 并处理失败投递

1. 对接人员准备事件接收地址，由运维人员确认其 HTTPS 主机已经加入允许清单。
2. 打开“开放集成 → Webhook”，点击“创建订阅”。
3. 选择“所属应用”，填写“订阅名称”“接收地址”，勾选“接收事件”，开启“启用订阅”，点击“保存订阅”。
4. 保存一次性展示的签名密钥，由接收方按“接入说明”配置验签。
5. 点击该订阅“投递”查看结果，或使用“全部投递”统一查询。

失败后先核对接收地址和接收方服务。在失败或过期记录上点击“重试投递”，系统会重新排队；“已重新排队”不代表对方已经接收成功，应继续查看最终状态。

事件可能重复或乱序，接收方需验签并按事件标识去重。自动投递最多尝试 5 次，24 小时后过期。轮换密钥后应同步更新接收方；“停用”订阅保留历史记录。

### 10.3 查看服务监控

1. 管理员打开“系统管理 → 运维中心 → 服务监控”。
2. 查看数据库是否可用、验证请求数、服务端错误率和 P95 延迟；P95 表示 95% 请求不超过的耗时。
3. 需要最新情况时点击“立即采样”。没有流量时显示“无样本”，不等于服务报错。
4. 发生问题时查看“后台任务错误”“服务事件”和“历史采样”，必要时点击“导出指标”交给运维排查。

### 10.4 创建备份并验证可恢复性

1. 打开“运维中心 → 备份与恢复”，确认“备份配置”为“已就绪”。
2. 点击“创建备份”，查看新增记录的状态，确认“成功”。备份文件保存在服务器配置的备份目录。
3. 在成功记录右侧点击“验证恢复”，再点击“开始验证”。
4. 等待结果，确认提示“备份已通过真实恢复验证”，列表显示“已验证”。

自动备份是否启用、执行间隔和保留份数以页面为准；该页面用于查看配置状态和执行任务。配置未就绪时，请运维人员检查备份目录、加密密钥和 PostgreSQL 工具。

恢复验证使用独立临时数据库。真正的灾难恢复和业务切换由运维人员按照[备份与恢复说明](backup-restore.md)执行。

## 11. 常见问题与处理方法

| 问题或提示 | 建议处理 |
| --- | --- |
| 网页打不开，或桌面连接不到服务 | 核对后台和 API 地址；确认系统服务已启动。在其他电脑上不要把服务器地址填成 `127.0.0.1` |
| 新账号登录后只有“账号安全” | 先按提示修改初始密码，再进入其他页面 |
| 找不到菜单或“生成卡密”按钮 | 请管理员检查角色和应用范围；渠道账号使用订单发卡 |
| 提示没有权限或记录不存在 | 核对当前账号、应用范围、渠道归属，以及记录是否仍可用 |
| 生成时找不到卡种 | 核对应用是否启用、卡种是否已创建且可发行，选择正确应用后重新加载 |
| 卡密无效，`LICENSE_INVALID` | 核对应用标识和完整卡密，避免使用卡密提示、卡密 ID 或客户访问码 |
| 激活超期，`ACTIVATION_DEADLINE_PASSED` | 已错过首次激活期限，联系商家处理重新发行；普通续期不会重设该期限 |
| 卡密已过期，`LICENSE_EXPIRED` | 办理续期，成功后重新激活 |
| 已禁用／已冻结 | 检查卡密和所属应用状态；核实后恢复或解冻，再重新激活 |
| 设备数量已满，`DEVICE_LIMIT_REACHED` | 查旧设备绑定，按规则释放旧设备或申请换绑 |
| 在线会话已满，`SESSION_LIMIT_REACHED` | 退出其他设备的会话，或请有权限的人员在后台核查并撤销不再需要的会话 |
| 换绑冷却／次数用尽 | 查看“设备换绑”的下次允许时间和剩余次数；确需售后调整时由有权限的人员填写原因处理 |
| 已退出软件却仍占设备名额 | “退出会话”保留设备绑定；要腾出名额，执行“释放当前设备”或后台“解绑设备” |
| 清除了本地授权，后台仍有会话 | 本地清除不会确认服务端退出；核查后台会话，必要时撤销或等待租约到期 |
| 心跳断开后操作不可用 | 恢复网络；租约已过期或会话已撤销时重新激活，离线等待不会自动增加可用时间 |
| 能激活，不能导出 CSV | 查看授权功能是否包含 `export`；旧卡不会随卡种修改自动获得新功能 |
| 强制升级，`CLIENT_VERSION_REQUIRED`／`CLIENT_UPGRADE_REQUIRED` | 使用符合最低版本要求的软件；由管理员核对真实版本与发布策略 |
| 续期提示需要订单，`CHANNEL_ORDER_REQUIRED` | 为该客户在“订单管理”创建并履约续期订单 |
| 渠道额度不足／未配置售价 | 管理员在渠道详情调整额度，或为对应卡种设置售价后再处理原订单 |
| 客户登录后看不到某张卡 | 核对客户、应用及订单关联；直接生成的卡密不会自动关联客户 |
| 客户访问码无效 | 核对是否用了最新访问码、客户是否被停用；需要时由商家重新生成并交付 |
| 卡密文件丢失 | 先检查本地下载和备份；订单交付保留期内可再次领取，直接发卡明文不能补回 |
| 登录已过期或返回登录页 | 重新输入账号密码；已开启双重验证时，再使用认证器验证码或未用过的恢复码完成登录 |
| 验证码无效或已使用 | 等待认证器生成新码，核对手机时间；也可使用一个未用过的恢复码 |
| 离线许可证不能签发 | 检查签名配置、正式卡是否已激活且有效、绑定是否已释放，以及设备标识是否一致 |
| 离线文件验证失败 | 核对应用、设备、可信公钥和文件期限，取得正确文件后再验证 |
| 操作过于频繁，`RATE_LIMITED` | 按提示稍后重试，不连续点击提交 |
| 发卡、续期、订单或额度调整时断网 | 保留原页面和待确认请求，先查询原结果，再用原请求重试，避免重复创建业务 |

Windows 测试台中，“释放当前设备”即使因冷却或网络问题未成功，也会结束本地权限。此时应核对后台绑定；本地停止使用不能作为设备已释放的证明。

仍无法处理时，向支持人员提供：操作时间、页面或软件名称、应用标识、相关卡密 ID／订单 ID、错误代码，以及界面提供的追踪编号。Windows 测试台可在“诊断与帮助 → 导出安全诊断”导出记录。共享截图前遮住完整卡密、密码、访问码、恢复码和凭证。

## 12. 新人练习与日常工作速查

### 12.1 用培训数据完成一次练习

由有权限的人员准备专用培训应用、账号和卡密，以下练习会实际改变培训授权状态。

1. 按第 2 章创建卡种，生成 1 张卡，保存 CSV；能说明完整卡密与卡密 ID 的区别。
2. 在 Windows 测试台激活，完成基础操作和 CSV 导出；回后台找到对应设备和最近心跳。
3. 在后台禁用培训卡，在测试台点击“立即心跳”，确认授权被拒绝；恢复后重新激活。
4. 为培训卡续期 1 小时，核对新的到期时间，并在“操作日志”找到对应记录。
5. 冻结后查看暂停的剩余时间，再解冻并重新激活；能说明冻结与禁用的区别。
6. 新建培训客户，用发卡订单履约并下载交付；生成客户访问码，进入自助服务核对订单和授权。
7. 通过自助服务提交一次续期或换绑申请，在后台核对并审批，回自助页确认结果。
